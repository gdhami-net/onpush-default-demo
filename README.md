# onpush-default-demo

Companion repo for the post **"An eager component is only as eager as its
parent"** ([gdhami.net](https://gdhami.net) — link added when the post is live).

Angular 22 made `OnPush` the default change detection strategy and renamed the
old default from `Default` to `Eager`. `ng update` runs a migration that writes
`changeDetection: ChangeDetectionStrategy.Eager` into the components you already
had, so the upgrade preserves behaviour. Components generated afterwards are
`OnPush`, and an `Eager` component placed under one of those stops updating for
one specific class of change.

This repo measures which class.

## What it proves

The page mounts the same three children twice — once under a parent that kept
`Eager`, once under a parent written the way the v22 generator writes one. Both
branches read the same service, so every difference on screen is change detection
and nothing else.

| what changes | under the `Eager` parent | under the `OnPush` parent |
|---|---|---|
| a plain field, from a timer (zone.js) | updates | **stale** |
| a plain field, from a button on the root component | updates | **stale** |
| a plain field, zoneless, nothing else scheduling a pass | stale | stale |
| a signal read in the child's template | updates | updates |
| a click handled inside the child itself | updates | updates |
| a new input on the `OnPush` parent | updates | updates |
| `markForCheck()` on the child | updates | updates |

The zoneless row is the one that keeps the story honest: with no zone.js there is
no pass to skip, so a plain field mutation reaches neither branch and the parent's
strategy is not the reason.

## The tests

`npm run check` is `ng test`. Eighteen tests across three files, named for the
cases they cover:

- `src/app/strategy-defaults.spec.ts` — the enum as shipped (`OnPush` is `0`,
  `Eager` is `1`, `Default` is the deprecated alias and also `1`), that a
  component with no `changeDetection` key compiles with `ɵcmp.onPush === true`,
  and the `change-detection-eager` entry in `@angular/core`'s `migrations.json`.
- `src/app/zone-change-detection.spec.ts` — the zone.js cases, with
  `provideZoneChangeDetection()` in the TestBed providers.
- `src/app/zoneless-change-detection.spec.ts` — the same scenarios with the v22
  default, which is zoneless.

Nothing sleeps. `zone.run()` is what makes zone.js schedule a pass and
`fixture.whenStable()` waits for that scheduled pass, so every before/after state
is chosen rather than raced. One test uses a real `setTimeout(…, 0)` inside the
zone to show a genuine macrotask behaving the same way, and it awaits a promise
resolved from inside the callback rather than waiting on a clock.

## The migration

`migration-fixture/` holds the pre-migration shapes and `expected.diff`, the real
output of `ng update @angular/core --migrate-only --name=change-detection-eager`
on Angular 22.1.6, including the two cases the migration leaves alone: a
component declared inside a `describe` block, and — in a project generated by the
v22 CLI — spec files as a whole. See `migration-fixture/README.md`.

## Run it

```bash
npm install
npm run check
```

`npm start` serves the page, where a timer pushes a new price once a second into
a plain field. The left column ticks, the right column does not.

Angular 22.1.6, TypeScript 6.0.3, Node 26.1.0, jsdom rather than a real browser.
Not repeated on Linux.
